Small, well-defined engagements for teams building web applications and APIs. No blanket security guarantees. Just careful testing, evidence, and a report your developers can act on.

WHAT I CAN HELP WITH
01 / RELEASE

Pre-launch workflow review

Test the journeys customers actually rely on: creating an account, completing a booking, changing a setting, applying a price or discount, or recovering from a failed request. The output is a prioritized defect log, not a vague thumbs-up.

Typical coverage

  • Core user journeys and edge cases
  • State persistence and error handling
  • Pricing and booking consistency
  • Reproducible defect reports
02 / AUTH

Account & access-control review

A narrow review of how identities, permissions and state interact. Working with approved test accounts and a defined environment, I examine whether the application enforces the right rules at the API boundary.

Typical coverage

  • Cross-account object access (BOLA)
  • Role and function-level authorization
  • Account and session lifecycle
  • Evidence and remediation notes
03 / RETEST

Regression checks for APIs

Turn a reproduced issue into a check that can be replayed. For suitable scopes, I write or adapt small test scripts and verify the same workflow before and after a fix. A straightforward test that catches a regression is more valuable than an impressive dashboard nobody trusts.

Typical coverage

  • HTTP request and response validation
  • Before/after fix comparison
  • Python-based test utilities where suitable
  • Developer-ready handoff
HOW THE WORK RUNS

Clear scope. Clear evidence. Clear handoff.

01

Agree the boundary

Identify which workflows, accounts, test environment and permissions are in scope.

02

Run the checks

Establish expected behavior, test alternatives and record observed responses.

03

Write what happened

Provide reproduction steps, evidence, impact limits and prioritised recommendations.

04

Verify the fix

Perform agreed retesting and report what changed and what remains unverified.

Scope matters: this is not a promise of full penetration testing, compliance certification, or a comprehensive audit. Quotes and timelines depend on the application and access available. Production testing requires explicit authorization.
